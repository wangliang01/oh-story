# story-conception · 中文小说构思总路由

把一篇小说从"一个想法"推到"一份可写的故事圣经"的总入口。本 skill 不直接产出内容，而是：**判断用户现在需要哪一块 → 读取并执行对应子 skill → 把结果写回 story-bible.md**。

## 何时使用
- 用户想启动/继续一次小说构思会话（"帮我构思""接着上次聊""继续"）
- 用户带已有大纲、草稿或写崩的片段来，需要先评审再补缺
- 用户点名要设计某一块（人物/情节/世界观……）

## 第零步 · 确定平台与篇幅（每次会话开始时确认）
1. 问平台与频道：**盐选**（男频）/ **番茄**（男频）。用户未指定时按当前会话语境判断或询问。
2. 加载平台规则：读取 `story-platform` 的 `references/<平台>.md`（按下方「参考资料解析顺序」定位），提取格式/节奏/情绪/卖点公式作为本会话的**平台约束**。
3. 确定篇幅档位：微小说 <3k ｜ 盐选短篇 8k~3w ｜ 中篇 3w~10w ｜ 长篇 10w+（番茄连载）。写入 `story-bible.md` 头部 `**篇幅**` 字段，格式：`<平台>·<档位>·<频道>`（如 `盐选·短篇·男频`）。
4. 明确告知用户当前平台约束，并把平台规则摘要传给随后执行的每个子 skill。
5. 用户中途改平台/篇幅 → 更新字段，并提醒哪些已写内容需要重审（平台影响格式与节奏，篇幅影响节长与钩子密度）。

## 第一步 · 定位故事圣经
1. 在项目根目录查找 `story-bible.md`。
2. 不存在 → 按模板创建。模板位置：本 skill 的 `references/story-bible-template.md`（按「参考资料解析顺序」定位，找不到则按记忆中的模板结构现场创建）。
3. 存在 → 完整读取，记录每节 `<!-- status: draft|complete -->` 和所有 `【待定·可改】`。

## 第二步 · 决定本回合做什么
按以下优先级决策，并向用户说明理由：
1. **用户点名**（"先设计人物""帮我看看世界观"）→ 直接进入对应块。
2. **用户带已有内容**（大纲/草稿/写崩片段）且圣经尚无评审记录 → 先走 `story-review`（评审优先原则）。
3. **自动推进**：按完成度补缺，顺序：核心卖点 → 读者与基调 → 人物 → 情节 → 世界观 → 评审。哪节还是 `draft` 就先补哪节。

## 第三步 · 执行
- 读取对应子 skill 的 `SKILL.md`（按「参考资料解析顺序」定位 `<name>/SKILL.md`），按其全部流程执行，并带着第零步确定的篇幅模式。
- 完成后如需验证作品是否达到可签约水准，提示用户可用 `story-qualify` 做签约级验证（并行子 Agent 评审 + 对标签约作品）。
- 子 skill 需要更完整示例时，同时读取它的 `references/` 下对应的 notes 文件（如 premise-notes.md / character-notes.md / plot-notes.md 等）。
- 执行结果写入 `story-bible.md` 对应章节，把该节 `<!-- status: draft -->` 改为 `<!-- status: complete -->`（仍留有待定的不算 complete）。
- 一个子 skill 完成后再看 frontier：若还有 draft 节且用户愿意继续，依次推进。

## 访谈主持规则（所有子 skill 通用，照此主持）
- 每轮最多 **5 个问题**，每个问题附 **1 个示例答案**。
- 用户答"不知道/没想过" → 根据已确定的题材给出 **2~3 个具体选项** 供挑选。
- 允许留白：用户可跳过，把该项标为 `【待定·可改】` 继续往下。
- 不要一次问完所有问题；每轮问完等用户回答，再进入下一轮。
- 全程用中文，语气直接、具体，不灌鸡汤。

## 参考资料解析顺序

跨 skill 引用（story-platform 的 references、子 skill 的 SKILL.md 等）按以下顺序查找，取第一个命中：`{项目根}/.claude/skills/` → `.opencode/skills/` → `.codex/skills/` → `.zcode/skills/` → `skills/` → `.agents/skills/`。找不到即视为未部署，提示先运行 story-setup。

## 与写作阶段衔接（oh-story 流水线）

story-bible.md 是构思阶段的工作文档。构思完成后进入写作时，按篇幅把圣经内容映射到 oh-story 项目结构：
- **短篇** → `{标题}/设定.md` + `小节大纲.md` + `正文.md`（用 `/story-short-write`）
- **长篇** → `{书名}/设定/` + `大纲/` + `正文/` + `追踪/`（用 `/story-long-write`）

映射要点：核心卖点/读者与基调 → 短篇 `设定.md` 或长篇 `设定/题材定位.md`；人物 → 角色设定文件；情节 → 细纲/小节大纲；世界观 → 设定文件。签约级验证用 `/story-qualify`，评审救场用 `/story-validate`。

## 完成标准
- `story-bible.md` 六节全部 `complete`、无 `【待定·可改】`；或
- 用户明确暂停/结束本回合；此时总结当前进度和下一步建议。
