# story-qualify · 签约级验证与调教

目标不是"及格"，是**能签约**。判断标准永远对标：同类题材里已经签约/上架/被买单的作品——读者凭什么为它们买单，你的作品凭什么让他们选你而不是它们。

## 何时使用
- 用户想验证 story-bible.md 或成稿能否达到签约水准
- 用户说"帮我看看到底平不平庸""能不能签约""够不够出版/上架"
- 需要给 story-* 系列 skill 做校准训练（调教回流）

## 输入
- story-bible.md（首选）；若已有成稿，一并提供路径（至少前三章 + 结尾一章）
- 题材与目标平台（起点/晋江/番茄/知乎盐选/出版……）——用户知道就说，不知道就问

## 流程

### 1. 收集评审素材
- 读取 story-bible.md 全文；有成稿则读前三章 + 结尾一章。
- 确认平台/篇幅/频道（从圣经头部读取，如 `盐选·短篇·男频`），必要时加载 `story-platform/references/<平台>.md` 作为验证基线（解析顺序见 story-conception「参考资料解析顺序」）。

### 2. 并行派出 4 个子 Agent
每个子 Agent 独立上下文，简报必须**把所需素材完整粘贴进去**（子 Agent 无法自行读文件）。每个子 Agent 报告限 300 字以内。

**子 Agent A · 签约编辑（市场/商业性/平台标准）**
- 素材：完整 story-bible.md（+前三章）+ 目标平台 + story-platform/references/<平台>.md 规则摘要。
- 简报："以目标平台签约编辑的视角评审：① 卖点是否足够独特且有市场（同质化=平庸）；② 前三章（或开头10%）留存力——读者会不会弃；③ 商业潜力（付费点/追更点/情绪价值）在哪；④ 平台格式与节奏是否达标（对照平台规则逐项）；⑤ 一句签约判断：会签/有条件签（列出条件）/不会签（为什么）。只写事实与判断，不写鼓励。"

**子 Agent B · 目标读者（沉浸/情绪）**
- 素材：完整 story-bible.md（+前三章）。
- 简报："以目标读者身份通读。报告：① 哪里看懂了、哪里没看懂；② 情绪峰值在哪、有没有被浪费；③ 读到哪一段会弃文、为什么；④ 主角是否值得共情（欲望/缺陷/底牌是否立得住）。"

**子 Agent C · 题材×平台专家（对标/基线）**
- 素材：题材 + 一句话卖点 + 篇幅 + 平台（story-platform/references/<平台>.md 规则 + `story-platform/references/genre-baselines.md` 题材基线）。
- 简报："凭行业知识找 2~3 部该题材、该平台已签约/高热度作品作对标：① 它们的共性基线（读者被什么吸引）；② 本作品相对基线的差距清单（缺了什么）；③ 平台格式与节奏基线逐项对照（导语 15~25 字/分节/节长/反转频率/黄金三章等）；④ 对照题材基线的导语公式/开头模式/反转母题逐项检查；⑤ 本作品有没有任何一项超过基线（如果有，这就是签约筹码）。只写事实判断。"

**子 Agent D · 逻辑审校（一致性/漏洞）**
- 素材：完整 story-bible.md。
- 简报："三遍检查：① 伏笔是否都有回收路径（或明确标记永不回收）；② 人物动机是否前后自洽（欲望/缺陷/底牌与情节是否咬合）；③ 世界观与情节有无硬伤（开挂点、规则破坏）。报告按 致命/重要/轻微 分级。"

**子 Agent E · 语言审校（文笔/节奏/盐选语感）**
- 素材：成稿全文（无成稿则跳过，标注"未成稿"）。
- 简报："逐段检查：① 是否用情绪词代替行为（'我很怕' = 不合格，应为'我喇叭不敢停'）；② 句子是否短、口语化、有画面（书面腔/形容词堆砌 = 不合格）；③ 每段是否在推进剧情/人物/情绪（废段标出）；④ 对话是否带信息/情绪/性格（寒暄式对话标出）；⑤ 节与节之间是否有钩子衔接。按 段号 报问题，限 300 字。"

### 3. 聚合为签约判定
把四份报告并列呈现（不合并、不改判）。然后给出主 Agent 的综合判定：
- **签约判定**：会签 / 有条件签 / 不会签
- **差距清单**：按"修了就能签"排序（P0 致命 / P1 重要 / P2 优化），每条给出具体改法
- **对标结论**：超过基线的地方（签约筹码）保留并放大；缺的补上
- **平庸检测**：明确回答"这是平庸作品吗"——平庸信号见 references/qualify-notes.md

### 4. 调教回流（校准循环）
验证后必做的一步：把这次评审中**暴露出 skill 体系没覆盖的问题**写回对应 skill 的 references 下 notes 文件：
- 编辑/读者发现的新弃文原因 → 补进 `story-validate/references/validate-notes.md` 的坑清单
- 题材专家发现的新题材基线 → 补进本 skill references/qualify-notes.md 的对标库
- 逻辑审校发现的常见漏洞类型 → 补进 story-review 或对应子 skill
- 回流后向用户报告："本次校准新增了 N 条，下一部作品会按新标准审。"

## 完成标准
- 五份子 Agent 报告 + 一份综合判定全部产出
- 差距清单按优先级可执行（每条都有具体改法）
- 校准回流已完成，并向用户说明改了什么
